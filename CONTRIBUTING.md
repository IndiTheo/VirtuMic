# Contributing to VirtuMic

Welcome to VirtuMic! This page will help you set up and contribute.

## Building

The project uses [Bazel](https://bazel.build/) as a build system. To ensure a consistent build environment, we use **Bazelisk**.

### Setup

1. **Install Bazelisk**: Bazelisk is a wrapper for Bazel that automatically downloads and uses the version specified in the `.bazelversion` file.
   * Follow the [official Bazelisk installation instructions](https://github.com/bazelbuild/bazelisk#installation).
   * In the directions below, `bazel` is assumed to be an alias to `bazelisk`.

2. **Android SDK & NDK**:
   The project requires the Android SDK and the Android NDK. You have two ways to configure these paths:

   #### Option A: Environment Variables (Global)
   Set these in your shell profile (`.bashrc`, `.zshrc`,...):
   ```bash
   export ANDROID_HOME=/path/to/your/Android/Sdk
   export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/<version>
   ```

   #### Option B: .bazelrc.local (Project-specific, Recommended)
   This is the recommended way if you want to avoid global environment variables. Add to `.bazelrc.local` file in the project root:
   ```text
   common --repo_env=ANDROID_HOME=/path/to/your/Android/Sdk
   common --repo_env=ANDROID_NDK_HOME=/path/to/your/Android/Sdk/ndk/<version>
   ```

3. **Build**: Run the following command to build the application (and the entire project):
   ```bash
   bazel build //:app
   ```

Build individual components:
```bash
bazel build //:core      # Core library
bazel build //:service   # Media session service
bazel build //:app       # Application (depends on all)
```

> [!NOTE]
> The Android NDK is required for Jetpack Compose compilation.

## Dependency Management

The project uses `rules_jvm_external` with Bzlmod for managing Maven dependencies. To ensure hermetic and reproducible builds, all dependencies are pinned in lockfiles.

### Lockfiles

- `MODULE.bazel.lock`: Bzlmod lockfile for Bazel module dependencies.
- Maven install lockfiles (generated by `rules_jvm_external`):
  - `android_install.json`: Android & androidx dependencies
  - `kotlin_install.json`: Kotlin compiler plugins & metadata
  - `security_install.json`: BouncyCastle for ADB TLS
  - `framework_install.json`: AOSP framework library including hidden APIs

### Updating Dependencies (Repinning)

If you modify the `maven.install` blocks in `MODULE.bazel` (e.g., adding a new artifact or changing a version),
you must update the corresponding lockfile.

To repin dependencies, run:

```bash
# Repin Android/third-party dependencies (main install)
REPIN=1 bazel run @unpinned_android//:pin

# Repin Kotlin compiler plugin dependencies
REPIN=1 bazel run @unpinned_kotlin//:pin

# Repin security dependencies
REPIN=1 bazel run @unpinned_security//:pin

# Repin framework dependencies
REPIN=1 bazel run @unpinned_framework//:pin
```

This will download the new dependencies, verify their checksums, and update the JSON lockfiles. You should then commit the updated lockfiles.

## Lint & Format

The project uses `ktlint` via Bazel for code style enforcement.

### Run Lint

To check for linting and formatting issues, run:
```bash
bazel run //:lint
```

### Run Format

To automatically fix most formatting issues, run:
```bash
bazel run //:format
```

## Testing

Run all tests
```bash
bazel test //...
```

### Unit Tests

Run all unit tests across the project:
```bash
bazel test //... --test_tag_filters=unit
```

Run tests for a specific module:
```bash
bazel test //virtumic-core/... --test_tag_filters=unit
bazel test //virtumic-service/... --test_tag_filters=unit
bazel test //virtumic-app/... --test_tag_filters=unit
bazel test //lib/privilege-hub:privilege_hub_tests --test_tag_filters=unit
```

### Manual Tests

Using either Ranchu or Goldfish emulator is recommended for testing the app:
```bash
bazel build //:app
adb install bazel-bin/virtumic-app/virtumic.apk
```

## Coding

At the time of writing, it's difficult to find an editor that supports dependency management
and code indexing for Bazel and Kotlin.

The recommended way to develop is Android Studio + Google's [ASwB plugin](https://plugins.jetbrains.com/plugin/9185-bazel-for-android-studio).
If you find another way to make code highlighting functional, let us know.

### Guidelines

- Modularity and architectural decoupling
- Compliance with state-of-the-art Kotlin and Android practices

## Pull Requests

1. Fork the repository.
2. Create a new branch for your feature or bug fix.
3. Ensure your code follows the existing project style.
4. Submit a pull request with a clear description of your changes.
